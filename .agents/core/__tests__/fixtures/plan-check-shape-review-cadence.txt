## Executive Summary

The Example training `/run-todo` in AdopterApp spent 34% of its 19.3 subagent-hours fixing review findings. It ran 32 reviews (about one per story) and 24 fix rounds, yet only about 9 reviews found a MAJOR or CRITICAL. The cause is in `/todo`: it writes a reviewer into every story's Ownership line, so `/run-todo` reviews each story.

This TODO:
1. Measures that run and today's vault `TODO_studio` run with a toolkit time-split tool, and writes an evaluation.
2. Writes one shared review-cadence reference that `/todo`, `/do` and `/run-todo` point to. Reviews happen per wave, at mid-epic (looking back and forward) and at the end of the epic. The reference states purpose and judgment, keeps a few firm lines, and requires a logged decision per wave.
3. Proves the new `/todo` against the old one by replaying the Example brief, judged blind against what actually happened. The new version is adopted only if it wins.
4. Applies the same purpose-and-firm-lines rewrite to the worst remaining skills.

Wave shape is role-based: measure → write → prove → spread. The adoption gate between waves 3 and 4 is a hard stop: if the new `/todo` does not win, waves 3b and 4 revert to the old workflows and skip the spread.

* **Story RC-1.1 (M): Toolkit session time-split tool**
