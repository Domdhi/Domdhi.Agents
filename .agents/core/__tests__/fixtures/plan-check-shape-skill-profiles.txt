## Executive Summary

Adopters choose skills with a hand-written `skillExclude` that the toolkit never checks. Excluding a skill that a kept workflow still invokes leaves a dead reference and gives no warning. This TODO adds three things. First, toolkit-owned profiles that allow-list skills and roles (`knowledge`, `agent`, `app`), selected with `"skillProfile"` and adjustable locally with `skillInclude` / `skillExclude`. Second, a closure check that fails closed when a kept skill or role still invokes a dropped skill in either name form (`review-x` or `/review:x`, `/name`). Third, removal of newly excluded, unmodified outputs on update. It also removes the stale `/sweep`, `/retro`, `/onboard` and optional `review-*` cross-calls from the kept workflows at their source. Finally, it modernises the most-used workflows' prose: shouted emphasis and duplicated rules go, every gate stays, and the result is measured before and after.

Wave shape: role-based by subsystem. Engine code (`_lib`, updater, render) and skill prose are disjoint file sets, so they run in parallel. The prose rewrite runs after the caller cleanup because both touch the same workflow files.

## Phase 1: Profiles and closure

**Goal:** A project selects a toolkit profile, the toolkit computes the effective skill and role set, and the toolkit refuses any set that leaves a dangling invocation.

---

### Epic SP-1: Profile engine

**Objective:** Make the skill and role selection toolkit-owned, dependency-closed and carried by fleet sync.

---

* **Story SP-1.1 (M): Profile resolution and reference-graph closure library**
  * **As a** toolkit maintainer, **I want** one library that resolves a project's effective skill/role set and lists dangling invocations, **So that** the updater, installer, render check and tests share one decision.
  * **AC:**
    * [x] New `.agents/core/_lib/skill-profiles.js` exports `loadProfiles(toolkitRoot)`, `resolveSelection({ toolkitRoot, config })` and `findDanglingReferences({ root, keptSkills, keptRoles })`.
    * [x] `resolveSelection` returns `{ excludedSkills: Set, excludedRoles: Set, keptSkills: Set, keptRoles: Set, errors: string[] }`. With no `skillProfile`, the behaviour matches today: every toolkit skill except `skillExclude`, and every role. With a profile, the kept skills are the profile's skills plus `skillInclude`, minus `skillExclude`. The kept roles are the profile's `roles` (every role when that field is absent).
    * [x] An unknown profile name, or an unknown skill or role name in a profile, `skillInclude` or `skillExclude`, is an error that names the offending value. The one exception is a renamed skill in `RENAMED_SKILLS`, which maps to its new name as it does today.
    * [x] The universe of skills is the toolkit's `.agents/skills/*` directories that contain a `SKILL.md`. The universe of roles is `.agents/roles/*.md`.
    * [x] `findDanglingReferences` scans every `.md` and `.json` file under each kept skill directory, and each kept role after `stripExcludedSkills` has removed the frontmatter and `## Skills` path references. It reports `{ caller, file, line, target, form }` for every reference to a dropped skill in any of these forms: the hyphenated name when it contains a hyphen (bounded by non-`[\w-]`), the `/name` slash form (not part of a path), a `skills/name/` path, and the colon command form derived from `.agents/adapters/workflows.json` (`review:x`, `/review:x`, `create:new-project`).
    * [x] A reference on a line that contains `if installed` or `when installed` (case-insensitive) is optional and is not reported.
    * [x] A role that names its own same-named skill (`qa-engineer` role → `qa-engineer` skill) is reported only when that skill is dropped and the role is kept. Frontmatter `name:` lines are not references.
    * [x] Unit tests cover the cases above, including each name form, the optional-line marker, the renamed-skill mapping, and that a self-reference in the skill's own directory is ignored.
  * **Estimate:** M
  * **Complexity:** 6
  * **Release:** core
  * **Risk tier:** deep — security-style control: a fail-closed validator for every adopter's delivery set (wide blast radius)
  * **Dependencies:** None
  * **Files:**
    * `.agents/core/_lib/skill-profiles.js` — new library
    * `.agents/core/_lib/__tests__/skill-profiles.test.js` — new tests
  * **Agent budget:** 0 modified, 2 created — within ≤5/≤2 cap
  * **Ownership:** production general-purpose; tests Main Agent (run-todo Step 2b); review fresh code-reviewer
  * **Research notes:** Name forms, verified against the live tree: `wf[name]` maps a workflow to `.claude/commands/{ns}/{x}.md`, and the colon form is `{ns}:{x}`. A prototype scanner (Key Findings 1) found the full caller list, which caused no false positives in the knowledge profile. `stripExcludedSkills` lives in `.agents/core/_lib/agent-merger.js:298` (it removes frontmatter skills and `## Skills` path bullets). `RENAMED_SKILLS` / `withRenamedSkills` live in `.agents/core/template-updater.js:96-101`; move or re-export them so the library does not require the updater (that would be a circular require, since the updater will require the library). Runtime helpers stay zero-dependency.

  * **AC:**

A new `loadExcludedRoles` returns `excludedRoles`. The default `toolkitRoot` is the running code's own root (`path.join(__dirname, '..', '..')`), so a fleet sync resolves against the workshop's profiles.
    * [x] Before any mutation, the update and install front doors run `resolveSelection` and `findDanglingReferences` against the source toolkit. Any error or dangling reference refuses the run with a new `PROFILE` front-door code.
