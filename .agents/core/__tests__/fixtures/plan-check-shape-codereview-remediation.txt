### Epic CR-1: Critical fixes

* **Story CR-1.1 (M): Symlink-safe writes & walks across the adopter trust boundary**
  * **Findings:** F23 (CRIT), F81 (CRIT), F86 (MAJOR), F55 (MINOR), F9 (MAJOR), F80 (MINOR).
  * **As a** maintainer running `fleet:sync`/`fleet:diverge` against adopter repos, **I want** every file write and directory walk to refuse to follow a destination/interior symlink, **so that** a malicious or accidental symlink in an adopter tree cannot cause arbitrary-file overwrite (F23/F86/F55) or disclosure (F81), and so symlinked skill dirs stop being silently skipped (F9).
  * **Files:** `.claude/core/_lib/zone-copy.js`, `.claude/core/_lib/skill-merger.js`, `.claude/core/_lib/agent-merger.js`, `.claude/core/template-updater.js`, `.claude/core/scaffold.js`, `.claude/core/_lib/file-walker.js`, `tools/fleet.js`, `tools/publish.js`; new `.claude/core/_lib/fs-safe.js` (shared primitive) + `__tests__`.
  * **AC:**
    * [x] New `_lib/fs-safe.js` exports `safeWrite(dstPath, bytes)` / `safeCopy(src, dst)` that `lstatSync(dst,{throwIfNoEntry:false})?.isSymbolicLink()` → `unlinkSync` then write (or abort + surface a security warning in run stats). Unit-tested with a symlinked destination proving the real target is untouched.
    * [x] All four write sites named in F23's detail route through it: `zone-copy.js:37-44`, `skill-merger.js:337-338`, `agent-merger.js:398-399`, `template-updater.js` `copyFile()` helper.
    * [x] `file-walker.js` `walkDir()` resolves symlinked dirs/files (via `Dirent` + `lstat`/`stat`) instead of silently dropping them (F9); symlink **cycles** are guarded (visited-realpath set). `tools/fleet.js walkRel()` (F81) and `tools/publish.js` walker (F80) either import the shared safe walker or gain the same symlink handling + cycle guard.
    * [x] `tools/sync-work.js` agent-doctrine patch (F86) writes via `safeWrite`.
    * [x] Regression test: a symlinked skill dir now syncs (F9); a symlinked destination is not followed (F23); `fleet diverge` does not read through a symlink (F81).
    * [x] `node .claude/core/gate.js test` green.

* **Story CR-1.2 (M): One correct shell command-boundary splitter for both guard hooks**
  * **Findings:** F58 (CRIT), F59 (MAJOR), F61 (CRIT), F62 (CRIT) — all in the guard hooks; same bug class (whitespace/keyword/wrapper evasion) that has recurred 3×.
  * **As a** developer relying on the guardrail + commit-guard hooks, **I want** command-position detection that recognizes real shell statement boundaries, **so that** `if true; then rm -rf .env; fi`, `sleep 1 & git commit -m …`, `sudo/env/time/nice/xargs git commit`, and `-m` payloads containing `$(...)` cannot bypass the hard-block or the pre-commit secret scan.
  * **Files:** `.claude/hooks/commit-guard.cjs`, `.claude/hooks/guardrail.cjs`, new shared helper in `.claude/core/_lib/` (e.g. `shell-command-split.js`) + `__tests__`.
  * **AC:**
    * [x] Shared helper tokenizes a Bash string into command-position starts, recognizing separators `; | & && || \n` **and** shell keywords `then do else elif {` **and** command wrappers (`sudo env time nice xargs command`) as introducing a new command head. Table-driven tests cover each evasion in the findings.
    * [x] `commit-guard.cjs gitCommitTail` (F58/F59): detects `git commit` at any command head, not just string-start/narrow-separator. Reproduced bypasses (`&`, `if/then`, `sudo git commit`) now blocked.
    * [x] `guardrail.cjs stripCommitMessages` (F61): must NOT blank `$(...)`/`` `...` `` inside `-m` before pattern/path evaluation — evaluate substitutions first, or strip only the literal message text. Test: `git commit -m "$(rm -rf ~)"` is still evaluated for the `rm -rf` path.
    * [x] `guardrail.cjs` zeroAccessPaths (F62): keyword-wrapped `rm -rf .env` still hits the non-escalatable hard-block. Test proves parity between bare and `if/then`-wrapped forms.
    * [x] Fail-closed: any parser exception in a blocking hook denies (never allows). `gate.js test` green including hook suites.

* **Story CR-1.3 (S): Eliminate execSync string-interpolation injection**
  * **Findings:** F31 (CRIT, `gate.js` dotnet `.sln` name), F33 (CRIT, `gen-timeline.js` `--base` ref), F54 (CRIT, `pull-request.js` `winQuote`).
  * **As a** user running gate/timeline/PR helpers in a repo with hostile filenames or refs, **I want** no shell string interpolation of untrusted values, **so that** a crafted `.sln`/`.slnx` filename, `--base` ref, or PR title cannot execute arbitrary commands.
  * **Files:** `.claude/core/gate.js`, `.claude/core/gen-timeline.js`, `.claude/core/pull-request.js` + `__tests__`.
  * **AC:**
    * [x] F31: dotnet invocation uses `spawnSync('dotnet', [verb, slnPath], …)` (argv array, no shell) — the solution filename is an argument, never interpolated into a shell string. Test with a filename containing `; ` / `$(…)`.
    * [x] F33: `gen-timeline.js` passes `--base` ref via argv array; add `git check-ref-format`-style validation or reject refs with shell metacharacters. Test with a hostile ref name.
    * [x] F54: replace `winQuote()` with argv-array `spawnSync` for `gh`/`az` (no cmd.exe string), OR fix the quoting to double embedded `"` per cmd.exe rules and add a test asserting a title containing `"` and `&` cannot break out. Prefer the argv-array route.
    * [x] Grep sweep: no remaining `execSync(\`…${userValue}…\`)` in these three files. `gate.js test` green.
